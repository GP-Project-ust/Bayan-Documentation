## 1. الهدف

الانتقال من سقالة سبرنت 0 إلى مساعد يجيب فعلياً: سؤال عربي → استعلام SQL مولّد وآمن ومُصحح ذاتياً → إجابة مع جدول وأثر تنفيذ كامل، عبر واجهة محادثة عربية RTL ببث حي، مع منظومة قياس قابلة للتكرار ونشر سحابي عام يعمل.

## 2. النطاق

**دخل:**
- وكيل SQL كامل: توليد بالـ LLM، تحقق AST، إصلاح ذاتي، تنفيذ قراءة فقط.
- البنية التحتية للوكلاء: المخطط، المشرف (توجيه حتمي)، الحالة المشتركة، مصنع النماذج، النموذج الوهمي.
- واجهة Next.js عربية RTL متصلة ببث SSE.
- منظومة التقييم: Golden Dataset وعدّادات القياس والأمان.
- النشر السحابي: Neon وVercel وGemini.

**لم يدخل (بالتصميم، لا بالتقصير):**
- وكيل RAG والمسار الهجين → سبرنت 2.
- وكيل التحليل والتقارير والرسوم والذاكرة → سبرنت 3.
- المصادقة والصلاحيات وسجل التدقيق والتهيئة الذكية → سبرنت 4 (طبقة التهيئة الذكية لم تبدأ تنفيذاً؛ تصميمها موثق في الأطروحة §4.3.3.1).
- التوجيه الذكي عبر LLM في المشرف → سبرنت 2 (وُثّق قرار تأجيله في كود المشرف نفسه).

## 4. الإنجازات التقنية

### 4.1 وكيل SQL الذكي (`backend/app/agents/sql_agent.py` — 412 سطراً)

- **التوليد**: عبر `get_llm("sql")` حصراً (ADR-002) بعد اختيار المشاهد المرشحة بمطابقة مفاهيم الكتالوج مع كلمات السؤال — إن لم تطابق شيئاً يُمرر الكتالوج كاملاً ويقرر النموذج.
- **التحقق AST عبر sqlglot** (الحاجز الأمني الفعلي، بديل الفحص النصي):
  - أنواع العبارات المسموحة: SELECT / CTE / UNION حصراً؛ يحظر INSERT وUPDATE وDELETE وCREATE وDROP وALTER وGRANT وREVOKE والأوامر (COPY، TRUNCATE...).
  - المصادر من مشاهد الكتالوج حصراً (ADR-001: لا وصول لجداول خام).
  - LIMIT إجباري يُضاف عبر شجرة AST نفسها لا باللصق النصي (يصمد أمام تعليقات `--` في نهاية الرد).
  - حاجز دوال خطرة: `pg_read_file`, `pg_write_file`, `lo_import`, `copy`, `dblink`, `dblink_exec`, `pg_sleep`, `pg_terminate_backend`, `pg_cancel_backend` (آخر خمسة أُضيفت بعد فحص اختراق ما بعد PR #17).
  - فحص تعدد العبارات بالفاصلة المنقوطة يتم بعد التحليل الشجري — لا يرفض `;` داخل النصوص.
- **الإصلاح الذاتي**: حتى 3 محاولات كلية بتغذية راجعة برسالة الخطأ (`build_repair_message`).
- **التنفيذ الآمن**: بدور قاعدة `bayan_reader` (قراءة فقط، مُختبر أمنياً في سبرنت 0)، مهلة اتصال 3 ثوانٍ ومهلة تنفيذ 5 ثوانٍ، واقتطاع النتائج مع وسم `rows_truncated` للمستخدم.
- **العرض**: `TablePayload` بسقف عرض 50 صفاً مستقل عن سقف التنفيذ، وتنسيق الصفوف المسترجعة داخل نص الإجابة للعرض الفوري.

### 4.2 البنية التحتية للوكلاء

- **المخطط** (`graph.py`): طوبولوجيا النجمة الموثقة في الأطروحة — supervisor + أربع عقد متخصصة (sql فعلي، وrag وanalyst وreporter عُلب موثقة تُملأ في سبرنتاتها).
- **المشرف** (`supervisor.py`): توجيه قاعدي حتمي بكلمات مفتاحية مرتبة بالأولوية — سريع ومجاني وقابل للاختبار بلا نموذج؛ التوجيه الذكي عبر LLM مؤجل بسبرنت 2 بقرار موثق في رأس الملف.
- **الحالة المشتركة** (`state.py`): 11 حقلاً مع reducer دمج لـ`agent_trace` يجمع أثر الوكلاء عبر السلسلة.
- **مصنع النماذج** (`llm/provider.py` — ADR-002): خمسة أدوار بدرجات حرارة مخصصة (supervisor وsql بـ0.0، rag بـ0.1، analyst بـ0.2، reporter بـ0.4) وخمسة مزودين (mock حتمي / ollama / openai / anthropic / gemini) بتبديل من متغير بيئة واحد.
- **مصنع Qdrant والتضمين** (`core/qdrant.py` — ADR-005): مجموعة `bayan_policies` بقياس جيب التمام، مزود mock حتمي من SHA-256 (نفس النص ← نفس المتجه) ومزود ollama بنموذج bge-m3 بـ1024 بعداً، وضبط idempotent للمجموعة.
- **عقد أحداث SSE** (`core/events.py` — ADR-003): meta → agent_end (لكل عقدة) → final، وerror صريح بدل القطع الصامت، مع أحداث محجوزة للقادم (agent_start / agent_token / clarification / tool_call) لضمان ثبات العقد أمام الواجهات.

### 4.3 واجهة المحادثة العربية (PR #16)

- Next.js 15 بواجهة RTL كاملة، عميل SSE يدوي عبر `fetch` (يتجاوز قيود EventSource مع POST).
- العرض: جداول النتائج، كود SQL، بطاقات أثر الوكلاء، ورسائل انتظار عربية.
- 12 مكوناً في `frontend/src/components/chat` مع طبقة أنواع TypeScript مطابقة حرفياً لعقود الخلفية.
- أداتا تطوير تعملان من اليوم الأول وتُعطلان إنتاجياً بـ`ENABLE_PLAYGROUND=false`: `/dev/playground` و`/dev/indexer` (فهرسة وبحث تجريبيان فوق مصنع Qdrant).

### 4.4 منظومة التقييم (PR #18 وPR #19)

- **Golden Dataset**: 33 سؤالاً عربياً في `evaluation/golden_dataset/questions.json` موثقة بالاستعلام المتوقع ونتيجة التحقق وحالة verified مثبتة بالتنفيذ.
- **العدّادات الأربعة** في `evaluation/runners/`، كلها تعمل بوضع mock بلا خادم وبلا اتصال خارجي (ADR-002):
  - `verify_dataset.py` — سلامة الطقم وإحصاءاته.
  - `run_safety.py` — 15 سؤالاً عدائياً (عربية وإنجليزية): حقن متعدد العبارات، DML/DDL صريح، دوال خطرة؛ يصنف محجوز/تسريب ويخرج برمز فشل عند أي تسريب.
  - `run_sql_accuracy.py` — دقة تنفيذ الاستعلامات مقابل المتوقع.
  - `run_latency.py` — زمن الاستجابة.

### 4.5 النشر السحابي (v0.1.1 — PR #20 حتى #23)

- **Neon** لاستضافة قاعدة PostgreSQL الجامعية التجريبية، **Vercel** لتشغيل الخلفية (مشغل Python مع ASGI)، **Gemini** كنموذج سحابي فعلي عبر `langchain-google-genai` (الخيار المجاني للفريق).
- **إصلاحات ما بعد الإقلاع** (اكتشفت بالنشر الحي لا بالاختبار المحلي — درس مهم):
  1. استخراج SQL من كتل محتوى Gemini 3+ (قائمة لا نصاً فقط).
  2. حجب `dblink` و`dblink_exec` و`pg_sleep` في حاجز الدوال الخطرة.
  3. تحويل العدّادات الثلاثة إلى psycopg3 (المثبت فعلاً) بدل psycopg2.
  4. تصحيح استعلام العدد الوهمي ليجمّع `SUM(student_count)` بدل عدّ صفوف الدفعات.
  5. فحص صحة يشير لحالة القاعدة الجامعية ويفحص المساند فقط عند تفعيله.

## 9. دروس السبرنت

1. **الحتمي قبل الذكي**: المشرف القاعدي والنموذج الوهمي مكّنا CI كاملاً واختبارات مستقرة من أول يوم، ولم يعطل تأجيل LLM أي عمل.
2. **النشر الحي يكشف ما لا يكشفه الاختبار المحلي**: كل إصلاحات ما بعد الإقلاع الخمسة ظهرت فقط على Vercel/Gemini الحقيقيين.
3. **العقود المشتركة أولاً (ADR-004) هي ما جعل التوزيع المتوازي ممكناً**: صفر تعارض جوهري بين فروع الأعضاء.
4. **فحص الاختراق بعد الدمج أضاف طبقة حماية حقيقية**: حجب dblink وpg_sleep لم يكن في التصميم الأول للحواجز.
